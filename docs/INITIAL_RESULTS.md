### Native register-only minimum-period diagnostic

The raw OpenSTA baseline logs show that the default `report_clock_min_period` result is the register-to-register metric; the separate `-include_port_paths` invocation produces the all-path value. The split baseline prints `period_min = 0.74 ns`, while the combined baseline prints `period_min = 0.00` and `fmax = inf`, which the parser correctly records as unavailable. The explicit rising-edge register-to-register path inventory nevertheless contains 106 split paths and 104 combined paths.

The explicit path-report arithmetic does **not** validate the native 0.74 ns split value. For split, the worst reported rising-edge register-to-register slack is 8.771 ns at a 10.000 ns clock period. `T - slack` is 1.229 ns; removing the 0.150 ns setup uncertainty gives 1.079 ns, and also removing the 0.035 ns library setup time gives 1.044 ns. None matches 0.740 ns within the 0.01 ns native print precision. For combined, the corresponding worst reported slack is 8.414 ns; the same arithmetic does not yield a native value because OpenSTA reports 0.00/inf. The cause of this discrepancy is not established from the available reports. Therefore no derived register-only period or Fmax is substituted for either native result.

The golden SDC now uses output loads of 20 fF on scalar control outputs and 30 fF on the GCD bus, consistent with the capacitance unit declared by the pinned Nangate45 Liberty. The earlier run used 0.02/0.03 fF and is superseded; its values are retained only as historical evidence.

**Interpretation:** The split architecture uses about 1.49% more Liberty cell area. OpenSTA's dedicated register-to-register minimum-period query returned no usable measurement for the combined architecture, so its register-only Fmax is unavailable. A separate path report confirms that register-to-register paths exist. The all-path period includes I/O port paths and is affected by the external input/output timing constraints. In particular, mutation M02 demonstrates that removing the `a_in` input delay changes the combined design's reported period from approximately 2.94 ns to 2.34 ns without changing the RTL. Therefore, the all-path Fmax values are measurements of the specified constraint scenarios, not a valid standalone comparison of the architectures' internal operating speeds. The split architecture's 0.740 ns register-to-register result is reported separately and should not be directly compared with the combined architecture's unavailable value.

## What the injected faults demonstrated

The corrected-load CI artifact for run #160 documents eight SDC scenarios for each architecture (16 STA log files total). Download the [raw STA matrix artifact](https://github.com/arshath-007/timingforge-gcd-sta-lab/actions/runs/42015328699/artifacts/13408368824) or the [static benchmark artifact](https://github.com/arshath-007/timingforge-gcd-sta-lab/actions/runs/42015328699/artifacts/13408887449). The static scorecard reports that the golden SDC passed and 7/7 controlled mutation patterns were detected (100% for this limited pattern set).
| Mutation | Observed STA evidence | Interpretation |
|---|---|---|
| M01 — missing primary clock | No minimum clock period can be reported; the logs report 138 and 140 unconstrained endpoints for the two architectures. | Without a clock, clocked timing analysis is not meaningful. |
| M02 — missing input delay on `a_in` | The combined design's reported minimum period changes from 2.94 ns to 2.34 ns and the selected setup path shifts to another input (for example, `b_in[19]`). The explicit OpenSTA setup check lists all 32 `a_in` bits as missing `set_input_delay` (32 input ports missing delay). | Removing an input budget can make the reported timing look better by excluding the intended input path. |
| M03 — missing output delay on `gcd_out` | 32 unconstrained endpoints are reported for each architecture, and the explicit setup check reports 32 output ports missing `set_output_delay`. | Output timing coverage is incomplete even though internal clocked paths can still be analysed. |
| M04 — broad register-to-register false path | The dedicated register-to-register setup report says `No paths found.` for the mutated case; the golden report contains register-to-register paths. | A broad exception can remove an entire path class from timing analysis. This mutation is deliberately invalid and exists only in the test suite. |
| M05 — near-match port typo | OpenSTA reports that `a_input*` does not match a design port. | Similar-looking names are not valid substitutes for the actual `a_in` bus. |
| M06 — missing hold uncertainty | Worst hold slack improves by exactly 0.050 ns in both architectures relative to baseline: combined -0.002 to +0.048 ns; split +0.005 to +0.055 ns. | Removing a hold-margin assumption makes the apparent hold result more optimistic. |
| M07 — zero clock period | Worst setup slack becomes -2.935 ns (combined) and -2.35 ns (split), with strongly negative TNS. | A non-positive clock period is invalid and produces a failing timing result. |

**Hold-timing note:** The combined architecture reports -0.002 ns worst hold slack under the golden SDC, while the split architecture reports +0.005 ns. Mutation M06 removes the 0.050 ns hold-uncertainty margin and improves the reported worst hold slack by exactly 0.050 ns in both architectures. This demonstrates the effect of the specified hold margin; it does not establish that the underlying design is inherently hold-safe. The combined result remains a small hold violation under the stated constraints. This educational pre-layout result should not be described as timing-clean or signoff-ready.

The static linter detects six controlled mutations as ERROR findings and flags M04 as a REVIEW finding; the scorecard counts all seven expected mutation patterns as detected. The STA run shows why several are important: paths can become unconstrained or disappear, and removing a margin assumption can improve reported slack without changing the RTL.

The 93-cycle and 124-cycle figures are historical maxima observed in a finite corpus, not proven algorithmic worst-case bounds. The randomized stimulus uses a fixed seed. Exact results may still depend on simulator semantics/version; finite-corpus maxima are not proven worst-case bounds.

## Reproduction

Run inside an OpenROAD Flow Scripts environment with Yosys/OpenROAD installed:

```bash
source /OpenROAD-flow-scripts/env.sh
make rtl-test
make python-test
make benchmark
make sta-matrix
```

The matrix script pins the Nangate45 platform files to the source revision listed above and writes raw logs under `build/reports/`, Yosys logs under `build/`, and a generated matrix summary in Markdown/JSON.

## Scope and limitations

- Single typical Liberty corner only; no MMMC analysis.
- No SPEF or extracted interconnect parasitics.
- Clock network is ideal in this pre-layout experiment; no clock-tree synthesis or routed clock effects are represented.
- No routed physical-design result is claimed.
- The 10 ns SDC is an illustrative teaching budget, not a real product interface specification.
- The Python SDC checker is an interface-specific pattern/coverage prototype, not a full Tcl/SDC parser and not proof of constraint correctness.
- A timing exception must be justified by design intent; the tool cannot decide that a false path is valid merely because the command parses.
- The Nangate45 platform is for educational benchmarking, not production signoff or a modern commercial process.
- These results must not be interpreted as silicon performance, power, or production PPA.

The next research stage is to measure the designs after a consistent physical implementation with defined clock-tree and parasitic assumptions, then add more representative blocks (FIFO and MAC) and multi-corner experiments.
